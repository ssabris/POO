Projeto P2 — Programação Orientada a Objetos

Sistema de Biblioteca

Arquitetura em 3 camadas com Java Swing, padrão DAO e MySQL. Documentação interativa do projeto.

Como as camadas se comunicam

A UI chama o DAO → o DAO acessa o banco → devolve objetos do model. Nunca pula camadas.

package ui
Camada de Interface — Swing
Janelas e painéis Swing. Mostra dados ao usuário, coleta entradas via formulários e ComboBoxes, e captura todas as exceções com catch (SQLException). Nunca acessa o banco diretamente.
⇅
package dao
Camada DAO — Data Access Object
Traduz objetos Java em comandos SQL e vice-versa. Cada método declara throws SQLException para que os erros apareçam na UI. Usa JOINs reais — sem objetos falsos.
⇅
package model
Camada Model — Entidades
Classes puras sem lógica de banco. Representam o mundo real: Pessoa, Leitor, Funcionario, Obra, Copia, Emprestimo, Reserva.
⇅
MySQL
Banco de dados
6 tabelas relacionadas: funcionario, leitor, obra, copia, emprestimo, reserva. Script completo em sql/banco.sql.

Todos os arquivos

Cada classe em seu próprio .java — Java não permite duas classes public no mesmo arquivo.

model — entidades do sistema
Pessoa.java
Classe abstrata. Define getIdentificacao() como método abstrato — força todas as subclasses a implementarem.
Leitor.java
Herda de Pessoa. Adiciona matricula. Implementa getIdentificacao() retornando "Leitor | Matrícula: ..."
Funcionario.java
Herda de Pessoa. Adiciona cargo. Implementa getIdentificacao() retornando "Funcionário | Cargo: ..."
Obra.java
Entidade independente com id, titulo e autor.
Copia.java
Agregação com Obra — uma cópia não existe sem uma obra, mas a obra existe de forma independente.
Emprestimo.java
Associação entre Leitor, Copia e Funcionario. Tem dataDevolucao que fica null enquanto o livro não volta.
Reserva.java
Associação entre Leitor e Obra. Tem todos os getters implementados.
dao — acesso ao banco
ConexaoDAO.java
Centraliza URL, USER e PASS. Único lugar para alterar credenciais. Todos os outros DAOs chamam este.
LeitorDAO.java
salvar, listarTodos, buscarPorId, excluir.
FuncionarioDAO.java
salvar, listarTodos, buscarPorId, excluir.
ObraDAO.java
salvar, listarTodos, buscarPorId, excluir.
CopiaDAO.java
salvar, listarTodos, buscarPorId, excluir. Usa JOIN com obra — sem criar objetos falsos new Obra(0,"","").
EmprestimoDAO.java
registrar, listarTodos, listarEmAberto, registrarDevolucao. JOIN completo com 4 tabelas.
ReservaDAO.java
registrar, listarTodos, excluir.
ui — interface gráfica swing
Main.java
Ponto de entrada. Abre a TelaPrincipal dentro do EDT do Swing via SwingUtilities.invokeLater.
TelaPrincipal.java
JFrame com JTabbedPane. Cada aba instancia um painel separado.
PainelLeitor.java
Formulário + JTable. Mostra getIdentificacao() na coluna — polimorfismo visível na UI.
PainelFuncionario.java
Mesmo padrão do PainelLeitor, com campo cargo.

Formulário + tabela de obras cadastradas.

Formulário com JComboBox de obras carregado do banco. Sem IDs digitados manualmente.

3 ComboBoxes (Leitor, Cópia, Funcionário) carregados do banco. Registra e lista todos os empréstimos.

Conceitos de OO aplicados

Os 4 pilares exigidos pelo enunciado — com onde aparecem no código.

🧬
Herança
Leitor e Funcionario herdam de Pessoa com extends. Ganham id, nome e todos os getters sem repetir código. A classe Pessoa é abstrata — não pode ser instanciada diretamente. 
public class Leitor extends Pessoa {
  // herda: id, nome, getId(), getNome()
  private String matricula; // atributo próprio
}
🔀
Polimorfismo
getIdentificacao() é abstrato em Pessoa e implementado diferente em cada subclasse. O mesmo método, chamado sobre um Leitor ou um Funcionario, produz respostas distintas — visível na coluna "Identificação" da JTable. 
// Leitor.getIdentificacao() retorna:
"Leitor | Matrícula: MAT-001"

// Funcionario.getIdentificacao() retorna:
"Funcionário | Cargo: Bibliotecário"
🔗
Agregação
Copia agrega Obra: uma cópia não pode existir sem uma obra, mas a obra existe independentemente. No banco isso vira FK NOT NULL. No DAO, um JOIN traz a obra junto — sem criar new Obra(0,"",""). 
public class Copia {
  private Obra obra; // AGREGAÇÃO
  // Copia depende de Obra para existir
}
↔️
Associação
Emprestimo associa Leitor, Copia e Funcionario: todos existem de forma independente e se relacionam nesse contexto. O mesmo vale para Reserva com Leitor e Obra. 
public class Emprestimo {
  private Leitor      leitor;    // ASSOCIAÇÃO
  private Copia       copia;     // ASSOCIAÇÃO
  private Funcionario funcionario; // ASSOCIAÇÃO
}
⚠️
Tratamento de exceções na UI
Todos os métodos DAO declaram throws SQLException. A UI captura dois tipos separados: validação do formulário (IllegalArgumentException) e erro do banco (SQLException), exibindo mensagens distintas com JOptionPane para cada caso. 
// Aviso amarelo — validação
} catch (IllegalArgumentException ex) {
  JOptionPane.showMessageDialog(..., WARNING);

// Erro vermelho — banco de dados
} catch (SQLException ex) {
  JOptionPane.showMessageDialog(..., ERROR);
}

Fluxo de uso

Ordem recomendada para configurar e usar o sistema do zero.

01
Execute o banco.sql
Rode o script no MySQL Workbench ou via terminal. Ele cria o banco biblioteca, as 6 tabelas e insere dados de exemplo (2 funcionários, 2 leitores, 2 obras, 3 cópias).
mysql -u root -p < sql/banco.sql
02
Ajuste ConexaoDAO.java
Abra src/dao/ConexaoDAO.java e altere USER e PASS com suas credenciais do MySQL. Só nesse arquivo — todos os outros DAOs usam ele.
03
Adicione o conector MySQL
Coloque o mysql-connector-j-x.x.x.jar na pasta lib/ do projeto e adicione às Referenced Libraries no VSCode (painel JAVA PROJECTS → + ao lado de Referenced Libraries).
04
Rode Main.java
Clique no ▶ acima do método main. A janela principal abre com 7 abas. Se der erro de conexão, a mensagem aparece em vermelho — verifique as credenciais.
05
Cadastre na ordem certa
Siga a dependência entre entidades: Funcionários → Leitores → Obras → Cópias. Cópias dependem de obras existirem no banco. Os dados de exemplo já cobrem isso.
06
Registre um empréstimo
Na aba Empréstimos, os ComboBoxes carregam Leitor, Cópia e Funcionário diretamente do banco. Selecione e clique em "Registrar Empréstimo".
07
Registre a devolução
Na aba Devoluções, só aparecem empréstimos em aberto (data_devolucao IS NULL). Selecione na tabela e clique no botão para registrar com a data de hoje.
08
Faça uma reserva
Na aba Reservas, escolha leitor e obra via ComboBox e registre. Para cancelar, selecione na tabela e clique em "Cancelar Selecionada".
