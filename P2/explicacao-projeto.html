Projeto P2 — Programação Orientada a Objetos

Sistema de Biblioteca

Arquitetura em 3 camadas com Java Swing, padrão DAO e MySQL. Documentação interativa do projeto.

Como as camadas se comunicam

A UI chama o DAO → o DAO acessa o banco → devolve objetos do model. Nunca pula camadas.

package ui
Camada de Interface — Swing
Janelas e painéis Swing com filtro em tempo real e edição inline. Captura três tipos de exceção separados: IllegalArgumentException (validação), IllegalStateException (regra de negócio) e SQLException (banco). Nunca acessa o banco diretamente.
⇅
package dao
Camada DAO — Data Access Object
Traduz objetos Java em comandos SQL e vice-versa. Operações críticas (registrar empréstimo, registrar devolução) usam transações atômicas que garantem consistência do estoque. Usa JOINs reais — sem objetos falsos.
⇅
package model
Camada Model — Entidades
Classes puras sem lógica de banco. Obra agora carrega codigoBarras, quantidadeTotal e quantidadeDisponivel. Emprestimo tem 3 datas e métodos isDevolvido() e isAtrasado().
⇅
MySQL
Banco de dados
5 tabelas relacionadas: funcionario, leitor, obra, emprestimo, reserva. Script completo em sql/banco.sql.

Operações CRUD

As quatro operações fundamentais aplicadas a cada entidade do sistema.

C
Create — Criar INSERT INTO tabela (...) VALUES (...)
Leitor Formulário com Nome e Matrícula. O DAO executa INSERT INTO leitor (nome, matricula). Matrícula tem restrição UNIQUE — duplicata exibe aviso específico.
Funcionário Formulário com Nome, Cargo e Matrícula Func. O campo matricula_func também é UNIQUE no banco. ativo = TRUE é definido por padrão no INSERT.
Obra Formulário com Título, Autor, Código de Barras e Qtd. Exemplares. O DAO insere quantidade_disponivel = quantidade_total no momento do cadastro.
Empréstimo Seleção via ComboBox de Leitor, Obra disponível e Funcionário. A data_prevista_devolucao é calculada automaticamente pelo prazo em dias. O INSERT e o decremento do estoque ocorrem em transação atômica.
Reserva Seleção de Leitor e Obra via ComboBox. Antes do INSERT, o DAO verifica se o leitor já possui 3 reservas ativas — se sim, lança IllegalStateException.
R
Read — Ler SELECT ... FROM tabela [WHERE ...]
Leitor listarTodos() retorna apenas leitores com ativo = 1 (Soft Delete). A lista popula tanto a JTable do painel quanto o ComboBox de Empréstimos e Reservas.
Funcionário listarTodos() filtra por ativo = TRUE. buscarPorId() é usado ao carregar dados para edição inline ao clicar na tabela.
Obra listarTodos() exibe todas as obras com estoque. listarDisponiveis() filtra WHERE quantidade_disponivel > 0 — usado exclusivamente no ComboBox de Empréstimos.
Empréstimo listarTodos() retorna todos com JOIN em leitor, obra e funcionário. listarEmAberto() adiciona WHERE data_devolucao_real IS NULL — usado na aba Devoluções.
Reserva listarTodos() retorna todas as reservas ativas com JOIN em leitor e obra, ordenadas por data. A contagem por leitor é verificada antes de cada novo INSERT.
U
Update — Atualizar UPDATE tabela SET ... WHERE id = ?
Leitor atualizar() edita Nome e Matrícula. A edição inline é ativada ao clicar em qualquer linha da tabela — o botão "Salvar" muda para "Atualizar" automaticamente.
Funcionário atualizar() edita Nome, Cargo e Matrícula Func. Mesmo padrão de edição inline. Matrícula duplicada exibe mensagem específica via SQLIntegrityConstraintViolationException.
Obra atualizar() edita Título, Autor, Código de Barras e Qtd. Total. decrementarDisponivel() e incrementarDisponivel() são chamados pelo EmprestimoDAO na mesma transação do empréstimo ou devolução.
Empréstimo registrarDevolucao() executa UPDATE emprestimo SET data_devolucao_real = ? e incrementa o estoque da obra em transação única — garantindo que nenhuma devolução fique sem atualizar o estoque.
Reserva Reservas não possuem edição direta — o fluxo esperado é cancelar e criar uma nova. O status de disponibilidade da obra referenciada é atualizado indiretamente via empréstimos.
D
Delete — Excluir DELETE / UPDATE ... SET ativo = 0
Leitor Soft Delete: UPDATE leitor SET ativo = 0. Antes de inativar, o DAO verifica se há empréstimos com data_devolucao_real IS NULL. Se houver, lança IllegalStateException e o leitor não é inativado.
Funcionário Soft Delete: UPDATE funcionario SET ativo = FALSE. O registro histórico nos empréstimos anteriores é preservado, pois a FK continua válida no banco.
Obra Delete físico: DELETE FROM obra WHERE id = ?. Exclusão só é possível se não houver empréstimos ou reservas vinculados — o banco lança violação de FK caso contrário.
Empréstimo Empréstimos não são excluídos — são encerrados via devolução (UPDATE em data_devolucao_real). O histórico completo permanece no banco para consulta na aba Empréstimos.
Reserva Delete físico: DELETE FROM reserva WHERE id = ? após confirmação. Chamado pelo botão "Cancelar Selecionada" na aba Reservas, liberando a vaga no limite de 3 por leitor.

Todos os arquivos

Cada classe em seu próprio .java — Java não permite duas classes public no mesmo arquivo.

model — entidades do sistema
Pessoa.java
Classe abstrata. Define getIdentificacao() como método abstrato — força todas as subclasses a implementarem.
Leitor.java
Herda de Pessoa. Adiciona matricula e campo ativo para Soft Delete. Implementa getIdentificacao() retornando "Leitor | Matrícula: ..."
Funcionario.java
Herda de Pessoa. Adiciona cargo, matriculaFunc (UNIQUE) e campo ativo. Implementa getIdentificacao() retornando "Funcionário | Cargo: ..."
Obra.java
Entidade com titulo, autor, codigoBarras, quantidadeTotal e quantidadeDisponivel. Método isDisponivel() retorna se há exemplares em estoque.
Emprestimo.java
Associação entre Leitor, Obra e Funcionario. Possui 3 datas: empréstimo, prevista e real. Métodos isDevolvido() e isAtrasado() encapsulam a lógica de status.
Reserva.java
Associação entre Leitor e Obra. Armazena a data da reserva e referências aos dois objetos associados.
dao — acesso ao banco
ConexaoDAO.java
Centraliza URL, USER e PASS. Único lugar para alterar credenciais. Todos os outros DAOs chamam este.
LeitorDAO.java
salvar, atualizar, listarTodos, buscarPorId, excluir. excluir() faz Soft Delete com verificação de empréstimos em aberto antes de inativar.
FuncionarioDAO.java
salvar, atualizar, listarTodos, buscarPorId, excluir. Inclui matricula_func. excluir() implementa Soft Delete.
ObraDAO.java
salvar, atualizar, listarTodos, listarDisponiveis, buscarPorId, excluir, decrementarDisponivel, incrementarDisponivel.
EmprestimoDAO.java
registrar (transação: INSERT + decrement de estoque), registrarDevolucao (transação: UPDATE + increment), listarTodos, listarEmAberto. JOIN completo com 3 tabelas.
ReservaDAO.java
registrar (com limite de 3 reservas por leitor), listarTodos, excluir.
ui — interface gráfica swing
Main.java
Ponto de entrada. Abre a TelaPrincipal dentro do EDT do Swing via SwingUtilities.invokeLater. Sem alterações.
TelaPrincipal.java
JFrame com JTabbedPane. Passa de 7 para 6 abas — aba "Cópias" removida.
PainelLeitor.java
Formulário + JTable com filtro em tempo real e edição inline. Trata IllegalStateException ao tentar inativar leitor com empréstimo em aberto.
PainelFuncionario.java
Mesmo padrão do PainelLeitor. Campo Matrícula Func. adicionado. Trata matrícula duplicada com mensagem específica.
PainelObra.java
Substitui também o antigo PainelCopia. Campos Código de Barras e Qtd. Exemplares adicionados. Tabela exibe disponibilidade em tempo real.
PainelEmprestimo.java
Campo Prazo (dias) calcula data prevista automaticamente. ComboBox de obras filtra apenas disponíveis. Tabela exibe status com indicador ⚠ ATRASADO.
PainelDevolucao.java
Lista empréstimos em aberto. Coluna Atrasado? calculada em tempo real. Devolução atualiza o estoque via transação.
PainelReserva.java
2 ComboBoxes (Leitor, Obra). Trata IllegalStateException de limite de 3 reservas com mensagem específica.

Conceitos de OO aplicados

Os pilares exigidos pelo enunciado — com onde aparecem no código.

🧬
Herança
Leitor e Funcionario herdam de Pessoa com extends. Ganham id, nome e todos os getters sem repetir código. A classe Pessoa é abstrata — não pode ser instanciada diretamente. 
public class Leitor extends Pessoa {
  // herda: id, nome, getId(), getNome()
  private String  matricula;
  private boolean ativo; // Soft Delete
}
🔀
Polimorfismo
getIdentificacao() é abstrato em Pessoa e implementado diferente em cada subclasse. O mesmo método, chamado sobre um Leitor ou um Funcionario, produz respostas distintas — visível na coluna "Identificação" da JTable. 
// Leitor.getIdentificacao() retorna:
"Leitor | Matrícula: MAT-001"
 
// Funcionario.getIdentificacao() retorna:
"Funcionário | Cargo: Bibliotecário"
↔️
Associação
Emprestimo associa Leitor, Obra e Funcionario: todos existem de forma independente. Na v2 a referência a Copia foi substituída por Obra diretamente. Reserva associa Leitor e Obra da mesma forma. 
public class Emprestimo {
  private Leitor      leitor;      // ASSOCIAÇÃO
  private Obra        obra;        // antes: Copia
  private Funcionario funcionario; // ASSOCIAÇÃO
}
⚠️
Tratamento de exceções na UI
A UI captura três tipos separados: validação de formulário (IllegalArgumentException), regras de negócio (IllegalStateException — obra sem estoque, limite de reservas, empréstimo em aberto) e erros do banco (SQLException), exibindo mensagens distintas para cada caso. 
// Aviso — validação de formulário
} catch (IllegalArgumentException ex) {
  JOptionPane.showMessageDialog(..., WARNING);
 
// Aviso — regra de negócio
} catch (IllegalStateException ex) {
  JOptionPane.showMessageDialog(..., WARNING);
 
// Erro — banco de dados
} catch (SQLException ex) {
  JOptionPane.showMessageDialog(..., ERROR);
}
🔒
Transações atômicas (DAO)
Registrar um empréstimo envolve dois comandos: INSERT na tabela emprestimo e UPDATE em quantidade_disponivel. Ambos são executados em uma transação única — se um falhar, o outro é revertido com rollback(), garantindo consistência do estoque. 
// EmprestimoDAO — transação atômica
conn.setAutoCommit(false);
try {
  stmt.executeUpdate(); // INSERT emprestimo
  obraDAO.decrementarDisponivel(...);
  conn.commit();
} catch (SQLException e) {
  conn.rollback(); throw e;
}

Fluxo de uso

Ordem recomendada para configurar e usar o sistema do zero.

01
Execute o banco_v2.sql
Rode o script no MySQL Workbench ou via terminal. Ele cria o banco biblioteca_v2, as 5 tabelas e insere dados de exemplo (2 funcionários, 2 leitores, 3 obras).
mysql -u root -p < sql/banco_v2.sql
02
Ajuste ConexaoDAO.java
Abra src/dao/ConexaoDAO.java e altere USER e PASS com suas credenciais do MySQL. Só nesse arquivo — todos os outros DAOs usam ele. A URL já aponta para biblioteca_v2.
03
Adicione o conector MySQL
O arquivo mysql-connector-j-9.7.0.jar já está na pasta lib/. Adicione-o às Referenced Libraries no VSCode (painel JAVA PROJECTS → + ao lado de Referenced Libraries) ou equivalente na sua IDE.
04
Rode Main.java
Clique no ▶ acima do método main. A janela principal abre com 6 abas. Se der erro de conexão, a mensagem aparece em vermelho — verifique as credenciais.
05
Cadastre na ordem certa
Siga a dependência entre entidades: Funcionários → Leitores → Obras. Ao cadastrar uma obra, informe o código de barras e a quantidade de exemplares. Os dados de exemplo já cobrem isso.
06
Registre um empréstimo
Na aba Empréstimos, os ComboBoxes carregam Leitor, Funcionário e apenas Obras disponíveis do banco. Defina o prazo em dias — a data prevista é calculada automaticamente.
07
Registre a devolução
Na aba Devoluções, só aparecem empréstimos em aberto. Empréstimos com prazo vencido são marcados com ⚠. Ao devolver, o estoque da obra é incrementado automaticamente.
08
Faça uma reserva
Na aba Reservas, escolha leitor e obra via ComboBox e registre. Cada leitor pode ter no máximo 3 reservas ativas. Para cancelar, selecione na tabela e clique em "Cancelar Selecionada".
